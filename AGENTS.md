# Contributing

This is the entry point for anyone who changes this repository, whether a person or a coding agent.

muster reads test reports after a test run and checks them against a testing policy ([POLICY.md](POLICY.md)). The project is pre-release: the tool, its tests and `docs/` arrive with 0.1.

## Code

- Python 3.11 or newer, standard library only. No third-party packages, at runtime or in tests.
- Code runs on Linux and Windows.
- Text files are plain ASCII with LF line endings.

## Tests

```sh
python -m unittest discover -s tests -t . -v
```

The tests under `tests/` cover `tools/hygiene.py` today; the tests of the tool arrive with the tool.

Fixtures are synthetic; never copy names, reports or paths from another project. A report fixture names no real host or user: a JUnit `hostname` is `localhost` or empty, a JaCoCo `sessioninfo` id is `localhost-` followed by hex digits, and no fixture has a `user.name` property; hygiene checks these three.

Synthetic absolute paths in tests and fixtures use a POSIX root whose first folder has more than one letter (for example `/work/src/...`); a test that needs a Windows drive or device path builds it at run time, since hygiene treats any drive or device path in the repository as a local one.

Synthetic globs and relative paths also use folders whose names have more than one letter, since hygiene reads a one-letter folder after a slash as a Git Bash drive path.

## Checks

CI runs three checks:

- **gitleaks**, on every push and every pull request: over every fetched ref, every object and the working tree;
- **hygiene**, `python tools/hygiene.py`, on every push and every pull request: over the tree and over the commits of the change; run it locally before committing, and with `--range origin/main..HEAD` before pushing;
- **identity**, on pushes to branches other than `main` and on pull requests from branches of this repository: every commit must carry the project's commit identity.

## Identity

- Commits made inside this repository use the project's commit identity (the one the identity job in `.github/workflows/ci.yml` checks).
- Every commit in any pull request, forks included, must use a GitHub noreply email address for author and committer.

## Commits and pull requests

- Subject line in the imperative mood, at most 72 characters.
- A blank line, then a body that explains why the change is needed.
- Commit messages are plain ASCII without control characters and carry no email address other than a GitHub noreply address, sign-off lines included, except the one Dependabot adds.
- No `Co-authored-by` or other attribution trailers, and no "generated with" or "generated by" lines, in commit messages or pull request descriptions.
- No directive in a commit message that tells GitHub to skip CI.
- Pull requests follow the template: What, Why, How verified.

## No scanner suppression

The repository has no mechanism that silences a scanner:

- no `.gitleaksignore` file, anywhere;
- no inline gitleaks suppression markers;
- no edits to `.gitleaks.toml` or `.gitattributes`; both are pinned by hash.

If a scanner reports something, remove the finding from the change. Do not suppress it.
